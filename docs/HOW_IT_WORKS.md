# 내부 동작

이 추천기는 두 가지 생각을 섞어서 동작한다.
- **단어 겹침(TF-IDF):** 줄거리에 같은 말이 많이, 그리고 드문 말일수록 많이 겹치면 비슷한 영화 (2~3장)
- **줄거리 뜻(문장 임베딩):** 단어가 달라도 뜻이 비슷하면 비슷한 영화 (3-5장)

기본값인 혼합 방식은 `0.7 × 뜻 + 0.3 × 단어 겹침`이다. 왜 이 조합인지는 [임베딩 비교](EMBEDDING.md)에 있다.

```
  KMDb API ─┐                                 ┌ TF-IDF 행렬 ─┐            ┌─ 터미널 (recommender.py)
            ├─ collect_kmdb.py ─ movies.csv ──┤              ├ Recommender ┤
  공공 CSV ─┘   (수집·정제)        (영화 표)    └ embedder.py ─┘ (점수 섞기) └─ 검색 화면 (web.py + static/index.html)
                                                 (뜻 벡터, data/emb/)
```

## 1. 데이터 만들기 (`collect_kmdb.py`)

영화 표(`movies.csv`)를 만드는 단계다. 입력은 두 가지이고, 출력 형식은 같다.

| 입력 | 명령 | 출력 |
|---|---|---|
| KMDb API (2015~2025 극영화·애니메이션) | `python collect_kmdb.py --from 20150101 --to 20251231` | `data/movies.csv` |
| 공공데이터포털 영화상세정보 CSV (2022-11) | `python collect_kmdb.py --from-csv data/raw/kmdb_detail` | `data/movies_kmdb_csv.csv` |

### 1-1. API 수집
- 극영화와 애니메이션은 KMDb에서 유형이 달라서 따로 두 번 받는다.
- 한 번에 500건씩 받고(`listCount=500`), 응답의 `TotalCount`를 볼 때까지 `startCount`를 500씩 늘린다. 호출 사이에는 0.5초 쉰다.
- 받은 페이지는 `data/raw/극영화_20150101_20251231_00000.json`처럼 **원본 그대로 저장**한다.
  같은 페이지가 이미 있으면 다시 호출하지 않는다. 하루 호출 한도가 있어도 다음 날 이어서 받을 수 있고,
  정제 규칙만 바꿀 때는 `--from-raw`로 API 없이 다시 만든다.
- `--sample`은 1건만 받아 `data/raw/sample.json`에 저장한다. 문서와 실제 응답 구조가 다를 수 있어서, 본 수집 전에 확인하는 용도다.

### 1-2. 응답을 표의 한 줄로 (`to_row`, `csv_to_rows`)
KMDb 응답은 같은 필드가 여러 모양으로 온다. 예를 들어 줄거리는 `{"plot": [..]}`, `{"plot": {..}}`, `[..]` 중 하나다.
`as_list()`가 이걸 항상 목록으로 바꾼 뒤 꺼낸다.

| 표 열 | API 필드 | 공공 CSV 열 | 처리 |
|---|---|---|---|
| `id` | `DOCID` | `KMDB영화정보관리번호` | 중복 제거 기준 |
| `title` | `title` | `제명` | 검색 강조 문자열(`!HS`, `!HE`)과 HTML 태그 제거 |
| `year` | `prodYear` | `제작년도` | 정수 |
| `genres` | `genre` | `장르` | 구분자를 `|`로 통일, 비면 `기타` |
| `overview` | `plots.plot[].plotText` | `줄거리` | 여러 언어 중 **한국어만** |
| `keywords` | `keywords` | `키워드` | `|`로 통일 |
| `director` | `directors.director[].directorNm` | `크레딧명`·`인명` 짝 중 `감독` | 여러 명이면 `|` |
| `audience` | `audiAcc` | 없음 | 누적 관객 수 |
| `url` | `kmdbUrl` | 관리번호로 조립 | 결과 확인 링크 |

공공 CSV의 크레딧은 `감독,출연,출연,…`과 `이정민,이민휘,조현철,…`처럼 두 열이 같은 순서로 짝을 이룬다. 둘을 짝지어 `감독`인 이름만 뽑는다.

### 1-3. 정제 (`refine`)
단계마다 남은 건수를 출력해서 어디서 많이 빠지는지 볼 수 있다.

1. 줄거리 50자 미만 제외: 짧은 줄거리는 단어가 몇 개 없어서 추천이 거의 무작위가 된다.
2. 같은 `id`는 1건만 남긴다.
3. 제목과 연도가 같은 재개봉판은 1건으로 합친다. 관객 수가 있는 쪽, 줄거리가 긴 쪽을 남긴다.
4. 장르에 `에로`가 있으면 제외한다.
5. 1,000편이 넘고 관객 수가 절반 이상 채워져 있으면 관객 수 상위 1,000편만 남긴다. 관객 수가 대부분 비어 있으면 전부 쓴다.

공공 CSV 기준: `수집 4,727 → 줄거리 50자 이상 4,006 → 중복 제거 3,991 → 최종 3,991`

## 2. 영화를 벡터로 바꾸기 (`Recommender.__init__`)

### 2-1. 영화 한 편 = 토큰 목록 (`build_document`)
줄거리를 형태소 분석기 [kiwipiepy](https://github.com/bab2min/kiwipiepy)로 쪼개서 **일반명사, 동사, 형용사, 외국어**만 남긴다.
동사·형용사는 기본형으로 바꾼다(`쫓는다` → `쫓다`). 조사, 어미, 불용어는 버린다.

**등장인물 이름은 버린다.** 이름이 같다는 이유로 엉뚱한 영화끼리 이어졌기 때문이다
(→ [개발 과정](DEVELOPMENT_LOG.md#5-1차-점검-35에서-45로)). 두 단계로 거른다.

1. **형태소 분석 전:** KMDb 줄거리는 인물을 `기택(송강호)`, `‘상현’`처럼 쓴다. "괄호 앞 단어"와 "띄어쓰기 없는 6자 이하 따옴표 안 단어"를
   불용어 "사람"으로 바꾼다. 그냥 지우면 뒤의 조사(`‘우성’을` → `을`)가 떨어져 단어로 잡히기 때문이다.
   띄어쓰기가 있는 따옴표(대사)는 이름이 아니라서 그대로 둔다.
2. **형태소 분석 후:** 고유명사(NNP)를 버린다. 1단계 패턴에 안 걸린 이름(`소영은`)이 여기서 빠진다.

여기에 장르, 키워드, 감독을 **접두사가 붙은 토큰**으로 덧붙인다. 접두사를 붙이는 이유는 줄거리의 일반 단어와 섞이지 않게 하기 위해서다.
예를 들어 줄거리의 "가족"과 장르 "가족"은 다른 의미다. 붙이는 횟수가 곧 가중치다.

| 재료 | 토큰 예 | 횟수 | 이유 |
|---|---|---|---|
| 줄거리 | `형사`, `조직`, `쫓다` | 나온 만큼 | 추천의 핵심 재료 |
| 장르 | `장르:범죄` | 2 | 장르가 같은 영화가 조금 더 올라오게 |
| 키워드 | `키워드:복수` | 2 | KMDb가 정리한 키워드는 줄거리 단어보다 주제를 정확히 짚는다 |
| 감독 | `감독:봉준호` | 1 | 같은 감독 작품을 살짝 끌어올린다 |

**메타 키워드는 버린다.** 실화바탕, 소설원작, 시리즈, 극장판, 리메이크, 황금종려상처럼 내용이 아니라 출처·이력을 말하는 키워드다.
`원작`, `수상작`, `영화제`로 끝나는 키워드와 `META_KEYWORDS` 목록이 대상이다. 데이터에는 그대로 두고 추천 계산에서만 뺀다.

실제 예: 브로커(2022), 공공 CSV 기준 토큰 77개
```
줄거리: 세탁소를 운영하지만 늘 빚에 시달리는 ‘상현’(송강호)과 베이비 박스 시설에서 일하는 보육원 출신의 ‘동수’(강동원). …
        엄마 ‘소영’(이지은)이 아기 ‘우성’을 찾으러 돌아온다. …

토큰:  세탁소, 운영, 빚, 시달리다, 베이비, 박스, 시설, 일, 보육원, 출신, 거세다, 비, 내리다, 밤, … 아기, 데려가다, 엄마, …
       장르:드라마, 장르:드라마, 장르:가족, 장르:가족,
       키워드:세탁소, 키워드:세탁소, 키워드:베이비박스, 키워드:베이비박스, 키워드:입양, 키워드:입양, …
       감독:고레에다 히로카즈
```
인물 이름(상현, 동수, 소영, 우성)과 배우 이름이 모두 빠졌다. 원래 키워드에 있던 해외영화제수상작, 칸영화제는 메타 키워드라 빠졌다.
이름 규칙을 넣기 전에는 '상현'이 `상`, `현`으로 쪼개지고 '동수'가 일반명사로 남았다.

### 2-2. TF-IDF 행렬
scikit-learn의 `TfidfVectorizer`에 토큰 목록을 그대로 넣는다(`analyzer=lambda doc: doc`). 결과는 `영화 수 × 단어 수` 행렬이다.
공공 CSV 3,991편이면 3,991 × 7,128, KMDb API 7,456편이면 약 7,456 × 14,600이고, 대부분 0인 희소 행렬이다.

각 칸의 값은 대략 이렇게 정해진다.

```
TF-IDF(영화, 단어) = (이 영화에 이 단어가 몇 번 나오나) × log(전체 영화 수 / 이 단어가 나오는 영화 수)
```

- 한 영화에 많이 나올수록 크다(TF). 장르를 2번 넣으면 여기서 효과가 난다.
- 여러 영화에 흔하게 나올수록 작다(IDF). "외계인"처럼 드문 말은 크고, "가족"처럼 흔한 말은 작다.
- 행마다 길이가 1이 되도록 정규화한다. 줄거리가 긴 영화가 무조건 유리해지지 않게 하기 위해서다.

**흔한 말·희귀한 말 거르기**: 영화가 200편 이상이면 두 가지를 거른다.
- `max_df=0.5`: 영화 절반 넘게 나오는 단어는 구분력이 없다.
- `min_df=2`: 한 영화에만 나오는 단어는 다른 영화와 연결해 주지 못한다.

샘플 35편처럼 적을 때는 이걸 켜면 단어가 거의 다 걸러져서 끈다.

## 3. 추천 계산

### 3-1. 비슷한 영화 (`similar`)
1. 제목으로 영화를 찾는다(`find`). 공백을 무시하고 비교한다. `인터스텔라 (2014)`처럼 연도를 붙이면 연도까지 맞춘다.
   같은 제목이 여럿이면 관객 수가 많은 쪽, 관객 수가 없으면 최신작을 고른다. 못 찾으면 제목 일부가 겹치는 영화를 최대 5개 알려 준다.
2. 그 영화의 행 벡터와 모든 영화의 **코사인 유사도**를 구한다. 벡터 길이가 1이라 내적과 같고, 0(겹치는 단어 없음)에서 1(완전히 같음) 사이다.
3. 자기 자신과 유사도 0인 영화를 빼고 높은 순으로 자른다.

### 3-2. 본 영화 여러 편으로 추천 (`from_watched`)
본 영화들의 벡터를 **평균**해서 "내 취향 벡터"를 만들고, 그 벡터로 3-1과 같은 계산을 한다. 본 영화는 결과에서 뺀다.

### 3-3. 문장 검색 (`search`)
입력 문장을 줄거리와 같은 방식으로 토큰화하고, 학습된 단어 사전으로 벡터를 만든다(`transform`).
문장에 장르 이름이 그대로 들어 있으면 장르 토큰도 넣는다. 그래서 "복수를 다룬 **스릴러**"는 `복수`, `다루다`, `스릴러`, `장르:스릴러`가 된다.
사전에 없는 단어는 무시된다.

### 3-4. 추천 이유 (`_reasons`)
코사인 유사도는 두 벡터를 칸마다 곱해서 더한 값이다. 그래서 **곱이 큰 칸이 유사도에 가장 많이 기여한 단어**다.
상위 4개를 이유로 보여 준다.

```
브로커 → BATTLE BABY  유사도 0.241   이유: 아기, 부모
```

추천 이유를 보면서 엉뚱한 단어(예: 등장인물 이름, "특별", "과정")가 자주 보이면 불용어나 품사 규칙을 고친다.
이 프로젝트에서 튜닝의 주된 도구였다.

### 3-5. 줄거리 뜻으로 비교하기 (`embedder.py`, `method="embed"`)
TF-IDF는 글자가 같아야만 이어진다. 그래서 공개된 한국어 문장 임베딩 모델 `jhgan/ko-sroberta-multitask`로
줄거리를 **뜻을 담은 숫자 768개**로 바꾼다. 학습은 하지 않고 내려받아 쓰기만 한다.

1. 줄거리의 인물 이름을 TF-IDF와 같은 규칙(`clean_plot`)으로 "사람"으로 바꾼다.
2. 모델은 128토큰까지만 읽는다. 줄거리를 문장 단위로 이어 붙이다가 120토큰을 넘기기 직전에 잘라 조각을 만든다.
3. 조각마다 벡터를 만들고, 글자 수로 가중 평균한 뒤 길이를 1로 맞춘다.
4. 7,456편 전체를 처음 한 번 계산해 `data/emb/movies.<해시>.npy`에 저장한다(CPU 약 13분). 해시는 제목·줄거리로 만들어서 데이터가 바뀌면 새로 계산한다.

검색할 때는 이렇게 쓴다.
- **비슷한 영화:** 저장된 벡터끼리 곱하면 바로 유사도다(길이가 1이라 코사인과 같다).
- **본 영화 여러 편:** 벡터를 평균한 뒤 길이를 1로 맞춘다.
- **문장 검색:** 입력 문장을 같은 모델로 벡터로 바꾼다(약 40ms).

장르·키워드·감독은 임베딩에 넣지 않는다. 그 정보는 TF-IDF 쪽이 맡는다.

### 3-6. 섞기 (`method="hybrid"`, 기본)
```
혼합 점수 = 0.7 × 임베딩 유사도 + 0.3 × TF-IDF 유사도
```
임베딩은 뜻을 잘 잡지만 장르·키워드를 모른다. 예를 들어 겨울왕국 2가 "두려움, 진실을 찾아 떠나는 이야기"라는 뜻만으로 진격의 거인과 이어졌다.
TF-IDF 30%가 디즈니·뮤지컬 키워드로 이를 바로잡는다. 추천 이유는 방식과 상관없이 TF-IDF 기여 단어로 보여 준다.

## 4. 검색 화면 (`web.py`, `static/index.html`)

추가 설치 없이 파이썬 내장 `http.server`로 띄운다. 화면은 HTML 파일 하나에 CSS와 JavaScript가 들어 있다.

| 주소 | 하는 일 |
|---|---|
| `GET /` | 검색 화면 (`static/index.html`) |
| `GET /api/datasets` | `data/`에 있는 데이터 목록. API 수집본, 공공 CSV, 샘플 35편 중 파일이 있는 것만 |
| `GET /api/search?q=&mode=text\|similar&data=&top=` | 추천 결과(JSON). 비슷한 영화 모드면 기준 영화(`base`)도 함께 |
| `GET /api/titles?q=&data=` | 제목 자동완성 후보 15개 |

- **캐시:** `Recommender`는 데이터마다 처음 한 번만 만들어 메모리에 둔다. 형태소 분석에 몇 초 걸리기 때문이다.
  서버가 켜질 때 첫 데이터를 미리 만들어 둬서 첫 검색이 느리지 않다. 여러 요청이 동시에 만들지 않게 잠금을 건다.
- **응답 속도:** 만들어 둔 뒤 한 번의 검색은 행렬 곱 하나라 0.01~0.04초다.
- **화면:** 제목 입력은 `<datalist>`로 자동완성한다. 결과 카드의 "이 영화와 비슷한 영화"를 누르면 그 제목으로 다시 검색한다.
  사용자 입력과 영화 정보는 화면에 넣기 전에 HTML 이스케이프한다. 다크 모드는 시스템 설정을 따른다.
- `127.0.0.1`에만 열려서 같은 PC에서만 접속할 수 있다.

## 6. 한계

- **TF-IDF는 단어가 같아야만 이어진다.** 임베딩·혼합 방식이 이 문제를 푼다("깡패를 소탕하는 경찰" → 범죄도시). 단, 임베딩은 줄거리가 짧으면 약하다.
- **줄거리에 크게 기댄다.** 줄거리가 배경 설명 위주면 장르가 달라도 이어진다. 예: 공포 영화 휴게소가 여행 영화들과 이어졌다.
- **소품 키워드에 끌려간다.** KMDb 키워드에는 주제(빈부격차)뿐 아니라 소품(CCTV, 인디언, 생일파티)도 섞여 있다.
  드문 단어라 점수가 높고 2배 가중치까지 붙어서, 기생충이 CCTV가 나오는 스릴러들과 이어졌다. 키워드 가중치를 1로 낮추면 기생충은 나아지지만
  마션·범죄도시가 나빠져서 기획서대로 2를 유지했다(→ [개발 과정](DEVELOPMENT_LOG.md)).
- **감독 가중치가 약하다.** 1번만 넣어서 같은 감독 작품이라도 줄거리가 다르면 올라오지 않는다. 기생충에서 봉준호의 옥자, 미키 17이 나오지 않았다.
- **이름 규칙의 빈틈.** 괄호나 따옴표 없이 쓴 이름은 형태소 분석기가 고유명사로 알아볼 때만 빠진다.
- **인기를 모른다.** 유사도만 보기 때문에 낯선 영화가 상위에 많이 온다. KMDb 응답의 관객 수는 7,456편 중 6편에만 있어 쓸 수 없었다.
  KOBIS 관객 수를 섞는 것이 기획서의 다음 단계 후보다.
