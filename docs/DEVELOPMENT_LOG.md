# 개발 과정

2026-10-24, 기획서 「KMDb 영화 추천 로컬 예제」(하루 2~3시간 × 3일 목표)로 시작했다.
계획대로 안 된 부분과 그때 내린 판단을 시간 순서로 남긴다.

## 1. 출발점: 있다던 추천기가 없었다

기획서는 **샘플 35편으로 돌던 `recommender.py`가 이미 있다**고 전제했다.
TF-IDF + 코사인 유사도, 세 가지 기능(비슷한 영화, 본 영화 기반, 문장 검색), 장르 2배 가중치, 추천 이유 표시를 갖춘 것이었다.
그런데 PC 홈 폴더 전체를 찾아도 그 파일이 없었다.

- **판단:** 기획서에 적힌 기능 그대로 새로 작성했다.
- **비교용 샘플 35편:** 기획서의 "35편 버전과 비교"를 위해 `data/sample_movies.csv`도 새로 만들었다.
  점검 영화 5편(기생충, 범죄도시, 극한직업, 인터스텔라, 겨울왕국)을 포함하고, 줄거리는 테스트용으로 직접 요약했다(README에 명시).
- **확인:** 35편으로 세 기능이 모두 동작하는 것을 봤다. 범죄도시를 넣으면 신세계, 범죄도시2, 극한직업이 '조직, 형사'를 이유로 나왔다.

## 2. API 키가 통하지 않았다

수집 스크립트를 먼저 만들고 `--sample`로 응답 구조를 확인하려 했는데, 계속 이 응답만 돌아왔다.

```
{ "Error" : 인증키가 필요합니다. }
```

원인을 하나씩 걸러 낸 과정이다.

| 시도한 키 | 결과 | 알게 된 것 |
|---|---|---|
| 다운로드 폴더의 "영상자료원 api키" | 실패 | 사실 **공공데이터포털 개인 키**였다. 다른 프로젝트의 기상청 키와 같은 값 |
| 공공데이터포털에서 '한국영상자료원_영화정보DB' 활용신청 | 실패 | 이 항목은 API 유형이 **LINK**다. 포털은 안내만 하고, 실제 키는 KMDb 사이트에서 따로 받아야 한다 |
| 공공데이터포털 '영화진흥위원회_영화 상세정보' | 실패 | 이것도 LINK형이고, KOBIS(영화진흥위원회)라는 다른 기관 API다. KOBIS에 직접 보내도 "유효하지않은 키값" |
| KMDb 사이트에서 받은 20자 키 | 실패 | 키 없음, 엉터리 키와 **똑같은 응답**이라 원인을 구분할 수 없었다 |
| UUID 형식(36자) 키 | 실패 | KMDb, KOBIS 둘 다 거부 |

- **요청 방식 문제가 아님을 확인:** 안내문 예시 주소를 글자 하나 바꾸지 않고 XML·JSON 양쪽으로 보내 봤다. 결과가 같았다.
- **호출 한도 문제도 아님:** 이 키로 보낸 첫 요청부터 실패했다. 한도를 넘었다면 처음 몇 번은 성공했어야 한다.
- **결론:** KMDb 공식 가이드에 "개발계정을 신청하면 **심의를 거쳐** 서비스키가 발급"된다고 적혀 있다. 심의 전이라 서버가 키를 받지 않는 것으로 판단하고 승인을 기다리기로 했다.

**배운 점:** 공공데이터포털은 어떤 API를 신청하든 같은 개인 키를 보여 준다. 포털이 직접 중계하는 API(기상청 단기예보 등)에는 그 키가 통하지만,
LINK형 API에는 통하지 않는다. 상세 페이지의 'API 유형'부터 확인해야 한다.

## 3. 대체 데이터 찾기

키를 기다리는 동안 키 없이 쓸 수 있는 데이터를 찾았다.

**받은 JSON 덤프 (`kmdb_json.json`, 37MB)**
- 한국영상자료원 **소장자료 목록**이었다. DVD, 디지털 파일 등 10만 행이다.
- 제목, 감독, 국가, 연도는 있지만 **줄거리·장르·키워드가 없다.** 줄거리 기반 추천에는 쓸 수 없어서 버렸다.

**공공데이터포털 '한국영상자료원_영화상세정보' (2022-11)**
- 줄거리, 장르, 키워드, 크레딧이 모두 있었다.
- 파일 내려받기 버튼이 JavaScript로 동작해서 페이지 스크립트를 읽고 실제 다운로드 순서를 따라갔다.
  순서는 `selectFileDataDownload.do` → `check-limit.json` → `fileDownload.do`다.
- zip 안 CSV 파일 이름이 인코딩 문제로 깨져서 파이썬 `zipfile`로 이름을 cp949로 다시 읽어 풀었다.
- **한계:** 4,727편 중 단편이 88%이고 99%가 국내 독립영화다. 기획서의 점검 영화는 한 편도 없다.

**판단:** 기획서대로 하려면 결국 API가 필요하다. 그래도 정제, 가중치, 불용어 같은 튜닝은 미리 해 볼 수 있어서
이 CSV로 1차 점검을 진행했다. 수집 스크립트에 `--from-csv`를 추가해 같은 정제 규칙을 거치게 했다.

## 4. 터미널에서 한글이 깨지는 문제

Windows에서 Git Bash와 PowerShell 파이프를 거치면 한글 출력과 명령줄 인자가 cp949로 바뀌어 깨졌다.
점검 결과는 파이썬이 UTF-8 파일에 직접 쓰게 하고, 웹 API 확인은 `urllib`로 UTF-8 요청을 보내서 해결했다.
추천기 자체 문제는 아니었다. 일반 PowerShell 창에서 직접 실행하면 정상으로 보인다.

## 5. 1차 점검: 3/5에서 4/5로

공공 CSV에는 기획서 점검 영화가 없어서, 이 데이터 안에서 장르가 다른 장편 5편을 골랐다.
통과 기준은 기획서와 같다. 상위 5개 중 3개 이상이 납득되면 통과다.

**첫 결과: 3/5.** 보이스, 이 안에 외계인이 있다, 22는 통과했다. 브로커와 휴게소가 실패했다.
추천 이유를 보니 원인이 바로 보였다.

```
'브로커 (2022)'와 비슷한 영화
2. 떴다, 오빠 (2014)   이유: 소영, 후배, 반
3. 눈물 (2016)         이유: 소영
```

**등장인물 이름 "소영"**이 같다는 이유로 무관한 영화가 이어졌다. 휴게소는 "경수"였다.
단편은 줄거리가 짧아서 이름 하나가 유사도를 좌우한다.

- **조치 1:** 줄거리 토큰에서 **고유명사(NNP)를 뺐다.** 지명도 같이 빠지지만, 주제어는 키워드 토큰으로 따로 들어가니 손실이 작다고 봤다.
- **조치 2:** 추천 이유에 자주 보인 무의미한 말(특별, 과정, 지나다, 보이다, 후배 …)을 불용어에 넣었다.

**결과: 4/5.** 브로커가 2/5에서 4/5로 올랐다. BATTLE BABY, My son, 꿈을 여행, The Son of a River가 '아기, 보육원, 부모'를 이유로 나왔다.

**휴게소는 여전히 실패했다.** 줄거리가 "가족 여행 중 휴게소"라는 배경 위주이고, 공포를 말해 주는 키워드(공포영화, 살인사건)는
다른 영화에 거의 없어서 `min_df=2`에 걸렸다. 장르 가중치를 올리면 나아질 수 있지만, 기획서가 가중치를 유지하기로 했으므로 한계로 기록했다.

문장 검색 3개("복수를 다룬 스릴러", "엄마와 딸의 화해", "청년 취업과 가난")는 모두 납득할 결과였다.

## 6. 검색 화면 추가

기획서는 웹 화면을 범위에서 뺐지만, 터미널보다 확인하기 쉬운 화면이 필요해서 추가했다.

- **새 의존성 없음:** FastAPI나 Streamlit을 쓰면 편하지만 패키지가 늘어난다. 파이썬 내장 `http.server`와 HTML 파일 하나로 끝냈다.
- **기존 추천기 재사용:** `Recommender`를 그대로 불러 쓴다. 추천 로직은 터미널과 화면이 같다.
- **데이터 목록 자동 반영:** API 수집본(`data/movies.csv`)이 생기면 화면의 데이터 목록에 자동으로 나타나게 했다.

## 7. 키 승인 후: 7,456편으로 2차 점검 (2026-10-26)

**키는 처음 받은 20자 키 그대로였다.** 승인이 나자 같은 키가 통했다. 결국 원인은 심의 대기였다.

**응답 구조 확인:** `--sample`로 기생충 1건을 받아 보니 문서를 보고 만든 매핑과 정확히 맞았다. 고칠 곳이 없었다.
다만 1건이 290KB였다. 보니 `staffs`(스태프 목록)가 90%였다. 보통 영화는 작아서 전체 원본은 109MB로 끝났다.

**수집:** 극영화 6,873 + 애니메이션 1,026편, 500건씩 17번 호출. 최종 7,456편.
관객 수가 6편에만 있어서 "관객 수 상위 1,000편" 자르기는 규칙대로 건너뛰었다.

**점검표와 수집 범위가 서로 맞지 않았다.** 기획서 점검 영화 중 인터스텔라(2014)와 겨울왕국(2014 국내 개봉)은
수집 범위(2015~2025 개봉) 밖이었다. 같은 확인 목적의 범위 안 영화로 바꿨다: 마션(해외 우주 SF), 겨울왕국 2(애니메이션).

**1회차: 4/5지만 기생충이 약했다.** 범죄도시·극한직업·마션·겨울왕국 2는 통과. 기생충은 몬태나(키워드 "인디언"),
고속도로 가족(이유 "기우")이 올라왔다. 여기서 두 가지 문제가 보였다.

1. **인물 이름이 여전히 남았다.** "기우"는 형태소 분석기가 일반명사로 봐서 고유명사 제외 규칙을 빠져나갔다.
   KMDb 줄거리는 `기택(송강호)`, `‘상현’`처럼 쓰는 습관이 있어서, 이 패턴을 분석 전에 지웠다.
   처음엔 그냥 지웠더니 `‘우성’을`의 `을`이 떨어져 단어로 잡혔다. 불용어 "사람"으로 바꿔서 조사와 함께 사라지게 했다.
2. **메타 키워드:** 키워드 빈도를 보니 실화바탕(216편), 소설원작(152편), 시리즈, 극장판, 리메이크처럼 출처·이력 정보가 가장 흔했다.
   기생충도 해외영화제수상작, 황금종려상, 아카데미상이 있었다. 내용이 아니므로 추천 재료에서 뺐다.

**결과: 기생충은 나아지지 않았다.** 메타 키워드를 빼자 "황금종려상"으로 이어지던 어느 가족이 빠지고, CCTV 소품 키워드로
스릴러 3편이 올라왔다. 원칙적으로 맞는 처리를 했는데 한 사례는 나빠진 셈이다. 그래도 수상 경력으로 영화를 묶는 건
추천의 의도가 아니라서 되돌리지 않았다.

**키워드 가중치 1 실험 (채택 안 함):** 기생충 문제의 근본은 소품 키워드 × 2배 가중치다. 1로 낮춰 10편(API 5 + CSV 5)을 다시 돌렸다.

| 영화 | 가중치 2 | 가중치 1 |
|---|---|---|
| 기생충 | CCTV 스릴러 ❌ | 보조바퀴(과외·가족), 스픽 노 이블 등 가족 드라마 쪽 △ |
| 극한직업 | 형사 영화 ✅ | 열혈형사, 위장수사, 오퍼레이션 메콩 ✅ |
| 마션 | 우주탐사·NASA ✅ | 마션 인베이션 등 "화성"만 겹침 ❌ |
| 범죄도시 | 조직폭력배 ✅ | "나쁘다", "도시"가 이유로 섞임 △ |
| 겨울왕국 2, CSV 5편 | ✅ | 거의 같음 |

한 편을 위해 두 편을 잃는 거래라서 기획서대로 2를 유지했다.

**최종: 4/5 통과.** 문장 검색의 "~를 다룬", "~를 그린"이 검색어로 들어가는 문제도 다루다·그리다를 불용어에 넣어 고쳤다.

**35편과 비교:** 35편에서는 고를 영화가 적어 대부분 장르가 이유였다. 7,456편에서는 잠복근무, 위장경찰, 우주탐사, 낙오/고립처럼
구체적인 주제로 이어진다. 반면 인기를 모르니 낯선 영화가 많고, 기생충은 키워드가 없던 35편이 오히려 나았다.

**재배포하지 않기로 함:** 저장소가 공개라서 API 수집본(`data/movies.csv`)은 올리지 않았다.
기획서 주의사항대로 KMDb 이용약관의 재배포 조건을 확인하기 전이기 때문이다. 키만 있으면 같은 명령으로 다시 만들 수 있다.

## 8. 문장 임베딩 도입 (2026-10-26)

기획서의 다음 단계 후보 중 "문장 임베딩 비교"를 골랐다. TF-IDF의 두 약점(글자가 다른 비슷한 말, 소품 키워드)을 함께 볼 수 있어서다.
결과 전체는 [임베딩 비교](EMBEDDING.md).

- **모델 선택:** 한국어 문장 유사도용 공개 모델 `jhgan/ko-sroberta-multitask`. 학습 없이 쓰기만 한다.
  "형사들이 조직 폭력배를 소탕한다" ↔ "경찰이 깡패 무리를 일망타진한다"가 겹치는 단어 없이 0.81로 나와서 바로 썼다.
- **길이 문제:** 모델은 128토큰까지만 읽는데 줄거리 절반 이상이 더 길었다. 문장 단위 조각 → 길이 가중 평균으로 해결.
- **기존 코드 재사용:** 인물 이름 정리 규칙을 `clean_plot()`으로 빼서 TF-IDF와 임베딩이 같이 쓴다.
  `Recommender`에 `method`(tfidf·embed·hybrid)만 추가해서 기존 명령과 테스트는 그대로 동작한다.
- **화면에서 몰래 계산하지 않기:** 임베딩 계산은 13분 걸려서 `python embedder.py`로 미리 만들고, 화면은 만들어 둔 것만 쓴다.
- **pandas 3 함정:** 독립영화 데이터에서 계산이 실패했다. 제목이 빈 영화가 있었는데, pandas 3은 `astype(str)`이 빈 값을 문자열로 바꾸지 않는다.
  `fillna("")`를 먼저 하도록 고쳤다. 기존 캐시 키는 빈 값이 없어서 그대로 유지됐다.

**평가를 공정하게 하려고:** 사람 눈 점검만으로는 주관적이라, 어느 방식도 직접 쓰지 않는 정보로 채점하는 대리 지표를 만들었다(`evaluate.py`).
시리즈 찾기(제목은 두 방식 모두 안 봄), 애니메이션 일치(KMDb '유형'은 두 방식 모두 안 봄)가 그것이다.
장르 일치도 냈지만 TF-IDF가 장르를 직접 쓰니 TF-IDF에 유리하다고 표시했다.

**결과와 결정:** 혼합(뜻 70% + 단어 30%)을 기본으로 했다.
- 대리 지표: 시리즈 찾기 47.5 → **52.3%**, 애니메이션 일치 53.6 → **62.3%**, 장르 일치 77.9 → 76.6%(TF-IDF에 유리한 지표).
- 점검표: TF-IDF 통과작을 대부분 유지하면서 기생충의 CCTV 문제가 사라졌다.
- 임베딩 단독은 채택하지 않았다. 겨울왕국 2가 진격의 거인과 이어지는 등 장르·키워드를 모르는 실수가 있었다.
- 바꿔 말한 문장 검색에서 가장 크게 좋아졌다. "깡패를 소탕하는 경찰"로 겹치는 단어 하나 없이 범죄도시를 찾았다.

**작업 중 실수:** `.gitignore`를 PowerShell로 고치다가 한글 주석을 잘못된 인코딩으로 읽어 다시 쓰는 바람에,
`data/movies.csv` 규칙이 주석 줄에 붙어 무시되지 않게 됐다. 커밋 전에 발견해 복구했고, 수집본이 커밋된 적은 없다.

## 9. 남은 일

1. 인기 가중치: KMDb 관객 수는 쓸 수 없어서 KOBIS 관객 수를 섞는다. 낯선 영화가 상위에 몰리는 문제를 줄인다.
2. 혼합 비중(0.7)과 다른 임베딩 모델 비교. 대리 지표 하나에 맞추면 과적합이 될 수 있어 점검표와 함께 본다.
3. 감독 가중치 실험: 기획서가 기대한 "같은 감독 작품 상위"가 나오지 않았다.
4. KMDb 이용약관에서 데이터 재배포·서비스 활용 조건 확인.
